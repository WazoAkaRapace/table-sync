# Repository Guide

**Standalone monorepo** — React 19 + Fastify 5 + better-sqlite3 character sheet, inventory manager & combat tracker for D&D 5e (French). Deployed via Docker. Repo: `github.com/WazoAkaRapace/table-sync` (« Table Sync » — le compagnon de campagne partagé, pour le MD et les joueurs).

### Structure
```
apps/api/      Fastify API (better-sqlite3, JWT auth, WebSocket sync)
apps/web/      React + Vite + Tailwind v4 frontend
packages/shared/  Shared TypeScript types + D&D 5e SRD rules engine
data/          Seed JSON (646 items, 490 spells, 964 monsters) + SQLite DB
scripts/       Import/translate scripts + rules test suites
site/          Marketing site (static, zero-build) — GitHub Pages
biome.jsonc    Linter + formatter config (whole monorepo)
```

### Commands
```bash
npm install              # Install all workspace deps
npm run dev              # Start API (port 4000) + Web (port 5173) concurrently
docker compose up --build  # Docker: API on 4010, Web on 8080 (real user data lives here)
npm run lint             # Biome: lint + format check (CI gate, currently clean)
npm run lint:fix         # Biome: fix + format everything
npm run format           # Biome: format only
npm run import-items     # Fetch & convert SRD items (lb→kg)
npx tsx scripts/import-monsters.ts  # Import SRD bestiary (5e-drs, all sources)
npm run test-weapon-stats  # Weapon/monk/unarmed/fighting-style/sneak/extra-attack checks
npm run test-armor-stats   # AC/magic-armor/speed/wild-shape/unarmored-defense checks
npm run test-class-features # Class-feature catalog, resources, applyRest, pact table, crit range
npm run test-multiclass-rules # Multiclassage SRD 5.1 : pools, prérequis, niveau de classe, dés de vie
npm run test-api           # API integration suite + zero-raw-SQL gate (boots a throwaway server)
npm run test:e2e           # Playwright browser E2E (boots its own throwaway API + vite stack, fresh e2e.sqlite)
npm run site               # Marketing site: assemble site/assets from docs/ + serve on :4188 (no-cache)
npm run screenshots        # Regenerate README's docs/screenshots/*.png (isolated stack + Playwright)
```

### Key conventions
- **All weights in kilograms** (French SRD metric values from 5e-drs.fr/AideDD.org)
- **Everything in French** — UI text, item/spell/monster names, descriptions
- **Import paths use `.ts` extensions** (tsx runtime, `moduleResolution: Bundler`); the API runs via tsx in Docker (no build step)
- **npm workspaces**: `-w` flags take package NAMES (`@table-sync/api`, `@table-sync/web`), not directory paths
- **TypeScript is v7 (native/Go port)** — `tsc -b` typechecking works, but there is NO classic JS API (`ts.createSourceFile` etc.); AST-based codemods need a standalone `typescript@5` install. Known baselines: web `tsc -b` is CLEAN (the former 7-error baseline in shared/index.ts resolveMagicArmorBase call sites was fixed 2026-08 — it is now a hard gate in CI and Dockerfile.web; any new error is a regression, fix it, don't baseline it); the API shows TS5097 `.ts`-extension noise everywhere (apps/api/tsconfig.json overrides resolution to NodeNext, which forbids `.ts` imports — the API is validated by tsx booting it, not by tsc)
- **Lint/format = Biome 2.5** — config MUST be `biome.jsonc` (comments in `biome.json` make it unparseable and Biome silently falls back to defaults: tabs + double quotes — has bitten us once). House style: 2 spaces, single quotes, semicolons, trailing commas, LF, width 100, sorted imports. `css.parser.tailwindDirectives: true` for Tailwind v4 at-rules. Excluded: `data/**`, `package-lock.json`, screenshots. Deliberate rule exceptions (documented in config): `noExplicitAny` (SQLite `as any` row-mapping convention), `noNonNullAssertion`, `noAutofocus` (modals focus their input), `useKeyWithClickEvents`/`noStaticElementInteractions` (mobile tap-outside overlays, div click zones)
- **Code style enforced by lint**: every `<button>` gets an explicit `type` (forms' submit buttons are `type="submit"`, everything else `type="button"`); form labels associate via `htmlFor`/`id`; intentional rule violations use `// biome-ignore lint/<group>/<rule>: <why>` — the suppression comment must sit on the line directly above the diagnostic (the formatter re-wraps long JSX tags, so prefer value-based keys or restructuring over suppressions anchored to attribute lines)
- **Shared rules engine** (`packages/shared/src/index.ts`): abilities, proficiency, encumbrance, spell slots, `computeAC`, `computeWeaponStats`, `computeUnarmedStats`, `computeSpeed`, wild shape, sneak attack, extra attacks, always-prepared spell tables (cleric domains, druid terrains, paladin oaths), hit-dice rolling, rests (`applyRest`), critical range, paladin aura. Web pages AND the combat API both call these — keep rules in shared, never duplicate
- **Class-feature catalog** (`packages/shared/src/classFeatures.ts`, re-exported by index.ts): 307 SRD 5.1 FR features (13 base classes + 39 subclasses incl. the 7 Clerc domains, 3 Paladin oaths, 3 Artificier specialists) with acquisition level, short templated description and optional resource (max formula + short/long rest recharge). Feature names follow the official AideDD translation (pages /regles/classes/… — Fougue, Inflexible, Conduit divin…), verified 2026-08 against one agent per class. Traits tab "Catalogue de classe" adds them in 1 click; `character_features.catalog_id` links rows back so `POST /characters/:id/rest` resets the right counters and recomputes max at the current level. The catalog is a HELPER, not an automation: every trait with a counter shows the « repos court / repos long » checkboxes (pre-checked on the SRD rule), and `reset_type` ('short'|'long'|'none', null = follow catalog) OVERRIDES the SRD rule — see `effectiveFeatureReset()`. `characters.subclass` (generic column, keys of `CLASS_SUBCLASSES`) covers Barbare/Barde/Ensorceleur/Guerrier/Magicien/Moine/Occultiste/Rôdeur/Roublard — Clerc/Druide/Paladin keep their dedicated columns. Full coverage matrix + roadmap: `docs/class-coverage-audit.md`
- **DB migrations = Drizzle, versioned, auto-applied on boot**: the schema source of truth is `apps/api/src/db/schema.ts`. Workflow: edit schema.ts → `npm -w api run db:generate` (drizzle-kit writes `apps/api/drizzle/00NN_*.sql` — commit it with schema.ts) → server boot applies pending migrations automatically (`runDrizzleMigrations()` in `db/drizzle.ts`, tracked in `__drizzle_migrations`). `schema.sql` + `COLUMN_MIGRATIONS` in `db/index.ts` are a **frozen baseline**: they still run on boot to create the base schema on fresh DBs but never grow — the `drizzle/0000_baseline` snapshot pins the diff chain (its SQL is deliberately a no-op; parity with the legacy path was verified structurally). Known unrepresentable detail: `users.username COLLATE NOCASE` lives only in schema.sql — re-add by hand if a future migration ever rebuilds that table. drizzle-kit needs drizzle-orm resolvable from the repo root too (it's a root devDep for that reason)
- **Queries = Drizzle query builder (raw SQL banned in routes/sync)**: every query in `src/routes/**` + `src/sync/**` goes through `getDrizzle()` (drizzle-orm 0.45, sync `.get()`/`.all()`/`.run()`), which wraps the SAME better-sqlite3 connection as the frozen baseline (pragmas + the `normalize()` SQL UDF apply to both). `npm run test-api` FAILS if any `.prepare(` site exists in those directories (`scripts/api-tests/coverage.ts` scrapes whole-file, multi-line literals included). Conventions: `cols(table)` from `db/projections.ts` builds a snake_case full-row projection so the mappers (`mapCharacter*`, `mapItem`…) keep reading raw column names untouched; `normalize()` searches and `COLLATE NOCASE` orderings live in `sql\`…\`` fragments; upserts use `.onConflictDoUpdate()` on the composite uniques; multi-write flows keep the native `getDb().transaction(() => …)` wrapper (Drizzle joins the ambient transaction on the shared connection — never nest `drizzle.transaction()` inside it); inserts needing the new id use `.returning().get()`, upserts re-SELECT by natural key (`lastInsertRowid` is unreliable on conflict). GOTCHA: in select-fields, drizzle renders `${table.col}` UNQUALIFIED (`"id"`) — a correlated subquery's own alias captures it; hand-qualify outer references (`… WHERE c.encounter_id = encounters.id`). `DB_SQL_TRACE=<file>` still records every prepared statement + callsite for debugging
- **better-sqlite3@13 ships prebuilds** — no node-gyp build needed; npm `allowScripts` warnings about its install script are benign
- **WebSocket sync**: events fan out per party via `apps/api/src/sync/`. Echo suppression is SERVER-SIDE (`ws.ts` skips the acting user's connections — they already have their API response), with `combat:change`, `character:change` and `campaign:change` EXEMPT (a user can be GM in one tab and player in another; the MD runs on several screens whose carnet must follow the clock). Client `markLocalMutation()` is a kept-for-compat no-op. Defensive pattern: after own combat mutations (e.g. initiative PATCH), the client bumps a local `combatRefresh` counter so the combat hub refetches even if the event never arrives. Client debounce coalesces per event kind (type + character + party); one-shot `concentration` payloads bypass the debounce entirely
- **HP is synced both ways**: PATCHing a player combatant (tracker) mirrors to the character sheet and vice versa, including the wild-shape shape bar and auto-revert at 0 with excess carry-over
- **Tailwind v4**: theme defined in `@theme` CSS block (not JS config). Custom colors: parchment, blood, ink, gold
- **Bottom sheets must be portaled** (`createPortal(document.body)`): `.card`'s `backdrop-blur` creates a containing block that breaks `position: fixed` inside it
- **Hooks must run before render guards** in CharacterInventoryPage (and anywhere with early returns): conditional hook counts crash React (#310 — has happened). The combat-indicator hooks sit above the guards with a comment saying so
- **Spell data**: 319 SRD + 171 expansion (Xanathar/Tasha/Fizban) from AideDD.org. Monster data: 5e-drs (all sources) + 60 adventure-module stat blocks + AideDD supplement — french-only `name_fr` column (no English `name` on monsters; spells have both)
- **OCR quirks in seed data**: catalog stores `'Crusader s mantle'`, `'Acid Arrow'` (Flèche acide de Melf) — check `WHERE name = ?` before adding name-keyed tables

### Rate limiting (`apps/api/src/rateLimit.ts`)
**Scoped to ERRORS ONLY by design** — a whole table shares one IP behind nginx, so counting successful requests would block the entire party. Counts only responses with status ≥ 400 (excluding 429 itself). Buckets (60 s window): auth-fail routes (`/api/auth/login`, `/api/auth/register`, `/api/parties/join`) 5/min; everything else 40/min. Client key: `x-real-ip` → first `x-forwarded-for` → `req.ip`. Tunables: `RATE_LIMIT_ERROR_MAX`, `RATE_LIMIT_AUTH_FAIL_MAX`, `RATE_LIMIT_WINDOW_MS`. **Gotcha**: register it by calling `errorRateLimit(app)` directly in `server.ts` — wrapping it in `app.register(...)` creates an encapsulated plugin scope where its onRequest/onResponse hooks never fire (silent no-op).

### Push notifications (Web Push / VAPID — `docs/push-notifications.md` fait foi)
Infrastructure générique d'envoi hors app : **tout nouveau déclencheur = UN appel serveur** `sendPushToUser(userId, {kind, title, body: {fr,en}, url, tag}, {ttl, urgency})` depuis `apps/api/src/push/send.ts` — fire-and-forget (jamais await sur le chemin critique), nettoyage automatique des abonnements morts (404/410), localisation par la `locale` de l'abonnement (le SW affiche sans traduire). Déclencheurs actifs : test (Mon compte) + combat dans `routes/combat.ts` — « lance ton initiative » quand le MD ajoute des PJ à une rencontre (clic → fiche `?combat=init` : saisie d'initiative déployée, carte dock mobile + tiroir desktop) et « À toi de jouer » (`notifyTurnPush`) quand le tour échoit à un PJ au démarrage ou à l'avance de tour (next-turn MD comme end-my-turn joueur ; clic → onglet Survie `?tab=survie`). Abonnements par appareil dans `push_subscriptions` (endpoint = clé naturelle, upsert) ; routes `/api/push/{config,subscribe,unsubscribe,test}` ; UI « Notifications » dans Mon compte. VAPID absent = fonctionnalité éteinte proprement (config `enabled:false`, test 503) — clés via `npm run vapid-keys`, JAMAIS regénérées en prod (rotation = orphelins tous les abonnés). Le service worker `apps/web/public/sw.js` est **push-only : AUCUN handler `fetch`** (le cache de déploiement reste inchangé — en faire un SW offline serait un chantier séparé) ; nginx le sert en `no-cache` via `location = /sw.js` (sinon la regex des assets l'immunise 1 an). Exige HTTPS en prod (TLS terminé en amont) ; iOS = PWA installée ≥ 16.4 seulement. Tests : module `push notifications` de `npm run test-api` (mock push HTTPS auto-signé trusted via `NODE_EXTRA_CA_CERTS` — web-push ne parle qu'HTTPS, et les clés de test doivent être de vraies P-256 ; les déclencheurs combat sont assertés en DÉCHIFFRANT les corps aes128gcm — `decryptPushBody`, le test détient la clé privée) + `e2e/notifications.spec.ts` (navigateur simulé).

### Emails transactionnels (Mailjet, provider-agnostique — `docs/transactional-emails.md` fait foi)
Envoi d'e-mails via un contrat provider (`apps/api/src/email/types.ts`) : Mailjet est l'adapter n°1 (`providers/mailjet.ts`, API Send v3.1 par `fetch` natif, zéro dépendance) ; **tout nouveau déclencheur = UN appel serveur** `sendEmail({to, ...template})` depuis `apps/api/src/email/send.ts` — fire-and-forget, un échec n'échoue JAMAIS la requête appelante, templates fr/en dans `email/templates/` (HTML inline-CSS seulement, les webmails retirent le reste). Tout-ou-rien comme VAPID : `MAILJET_API_KEY`+`MAILJET_API_SECRET`+`EMAIL_FROM_ADDRESS` (expéditeur VÉRIFIÉ chez Mailjet) absents = fonctionnalité éteinte (forgot-password/resend 503). Déclencheurs : **reset de mot de passe** — `POST /api/auth/forgot-password` **toujours 200 {ok:true}** (anti-énumération, cooldown silencieux 1/min/utilisateur), jetons 256 bits **stockés en SHA-256 seulement** dans `password_reset_tokens` (TTL 60 min, usage unique, 1 actif par utilisateur, `locale` figée à la demande), `POST /api/auth/reset-password` renvoie `{token,user}` (auto-login) et **vaut vérification d'adresse** (le clic prouve la boîte) ; **vérification d'adresse** — lien à l'inscription (TTL 24 h, `email_verification_tokens`), l'adresse ne se RETIRE plus (« »/null → 400, les comptes sans email sont un héritage d'avant son obligation) ; changement DIRECT si l'adresse actuelle n'est pas vérifiée, sinon **pending** (`users.pending_email`, unique) : l'ancienne vérifiée reste active jusqu'au clic sur le lien de la nouvelle (`POST /api/auth/verify-email`, public — 409 si claimée entre-temps, unicité re-vérifiée dans la transaction), et réenregistrer l'adresse ACTIVE annule un pending (purge du lien en vol) ; renvoi authentifié `POST /api/auth/verify-email/resend`. Routes publiques : allowlist du guard JWT + `TIGHT_ROUTES`. Lien absolu = `APP_URL` || en-tête Origin (`email/links.ts` `appLinkBase`). Pages web `/mot-de-passe-oublie`, `/reinitialiser-mot-de-passe`, `/verifier-email` (auto-login via `adoptSession` ; ne JAMAIS appeler /me depuis la page de vérification sans session — l'intercepteur 401 du client API redirige vers /login). `User` expose `emailVerifiedAt`/`pendingEmail` (chip + bandeau dans Mon compte). JWT stateless : un reset ne révoque pas les sessions existantes (7 j). Tests : module `emails transactionnels` de `npm run test-api` (faux Mailjet HTTP, `MAILJET_API_URL` redirigé, lookups PAR SUJET car l'inscription envoie un e-mail, `withoutEmail` second boot) + `e2e/password-reset.spec.ts` + `e2e/verify-email.spec.ts` (états Mon compte : session seedée réelle + /me stubbé — un faux jeton ferait 401-redirecter les composants globaux). Les deux compose passent VAPID_* et MAILJET_*/EMAIL_*/APP_URL depuis `.env`.

### Combat tracker UI
- **Desktop (lg+)**: `CombatWidget` is a left-edge mini drawer — collapsed = vertical tab pinned mid-left; expanded = `w-72` drawer with `drawer-enter` slide-in. The centering `translate-y-1/2` lives on an OUTER wrapper; the animated card is INNER, so the slide animation never fights the transform. The widget loads ONLY on the player's own sheet, scoped to the URL's party (one `/parties/:id/encounters` call per 30 s + one detail per own active fight — no `/api/parties` fan-out); real-time = WS `combat:change` for that party + a resync when the socket reconnects; `myCombatant` matches the SHEET's character (same rule as the mobile card), and the drawer header shows the encounter name
- **Mobile**: combat status is an always-visible card docked above the floating dock pill. On "your turn", the FULL dock pill gets `combat-turn-glow` (pulsing red box-shadow) — not just the hub button
- **Turn slash**: shared `components/TurnSlash.tsx` — `useTurnSlash(isMyTurn)` returns a boolean that goes true for ~1.4 s ONLY on the transition into your turn (never replays on collapse/expand); `<TurnSlash active />` renders the overlay. The `combat-slash-double` keyframe plays forehand AND backhand in one 1.15 s pass (not alternating per round); reduced-motion gets a static ring
- **Navigation**: combat tracker header has a "Ma fiche" action (via `useHeaderOverride`'s 3rd arg — memoize the action object, it's in the effect deps); combatant names link to character sheets when the combatant maps to a party character (view permission = party membership); `/party/:id/combat?enc=ID` deep-links straight into an encounter; the widget's "Voir le combat" uses that link
- **Multi-add**: `POST /api/encounters/:id/combatants/player` accepts `characterIds[]` (legacy single `characterId` still works), batch-inserted in one transaction; `AddPlayerModal` multi-selects with "Tout sélectionner"

Un seul `GET /campaign` charge tout ; onglet dérivé de `?tab=` (notes défaut), rafraîchissement silencieux sur `campaign:change`

- Tests : module « carnet du MD » de `npm run test-api` (gate GM 403, horloge, archivage jours, rebours, notes + ordre, quêtes + statuts)

### Rules engine coverage (SRD 5e, all in shared)
- AC: armor table with true light/medium/heavy types, DEX caps, shields, magic armor base resolution (`Armure (…)` description headers), class unarmored defense (Barbare 10+DEX+CON shield-ok, Moine 10+DEX+SAG shieldless, Ensorceleur draconique 13+DEX shield-ok), Défense fighting style
- Attacks: finesse/thrown/ranged/monk-DEX ability pick, weapon proficiency by class (editable `weapon_proficiencies`, null = class default), magic weapon base resolution + bonus, versatile 2h dice, martial arts die on monk weapons & unarmed (d4→d10), fighting styles (Archérie, Duel, Défense), sneak attack (Roublard), extra attacks (×2/3/4; Moine ×2@5), Champion crit range (19-20@3, 18-20@15 — chip on weapon cards), non-proficient ⚠
- Speed: Moine unarmored movement (3→9 m), Barbare fast movement, heavy-armor STR-min penalty (−3 m), encumbrance
- Spells: slot tables (full/half/pact/artificier — pact is RAW: 1 slot@L1, 2@L2, scaling slot level, 3@L11, 4@L17 all L5), cantrips/rituals/upcasting with scaled damage preview + healing preview (`spellHealingAtLevel`, green ✚ chip: dice + casting mod for the 5 +mod healers, flag `heal_adds_modifier` in the seed's damage_json `heal_at_slot_level` tables), concentration (single instance, CON save DD 10/½ dmg on damage, broken by incapacitating conditions & 0 PV), always-prepared domain/circle/oath spells (cleric `divine_domain`, druid `land_circle` under cercle Terre, paladin `sacred_oath`)
- Wild shape: CR gates by level (Lune: lvl/3 min 1), fly/swim gates, seen-beast list, 2 uses/short rest (unlimited at level 20 — Archidruide), rolled shape HP, elementals for Lune 10, combat-tracker integration
- **Multiclassage (SRD 5.1)**: `character_classes` rows are the source of truth (class_key/level/subclass_key/hit_dice_used/fighting_style/position); the flat `characters` columns stay denormalized (character_class = starting class, level = SUM — the CHECK 1-20 guards the total) and every reader MUST `attachCharacterClasses()` before `mapCharacter*`. Engine keystone: `classesOf(character)` resolves class lines for both storage generations (new `classes[]` or legacy flat columns) — all class-keyed rules evaluate at CLASS level (`classLevelOf`): rage/ki/sorcery counters (`classFeatureResourceMax`), Champion crit, paladin aura, martial arts, sneak attack, wild shape, expertise pools (summed). Extra Attack = MAX across classes (never summed); unarmored defense = ONE choice (`unarmored_defense` column, picker in Caractéristiques when ≥ 2 candidates); Moine/Barbare speed bonuses stack (distinct names). Spell slots = two pools (`computeSpellcastingPools`): Incantation (single class → own table incl. the half-caster trap; multi → SRD incastateur multiclassé table == `SPELL_SLOTS_FULL` at caster level full+⌊pal/rôd⌋+⌈artif⌉+⌊CO/EA tiers⌋) and pact (`pact_slots_used`, short-rest recharge, cross-pool casting allowed). Prereqs (`MULTICLASS_PREREQUISITES`) and gained proficiencies (`MULTICLASS_PROFICIENCIES_GAINED`) are ⚠ UI-only, never API-blocked (helper-not-automation). Legacy flat PATCHes (level/subclass columns) sync to class rows — a flat `level` applies its delta to the LAST line. `character_spells.class_source` tags each spell's originating class (unique stays (character, spell) — one source per spell, switchable). Hit dice tracked per line (mixed types displayed "3d10 + 2d8"); long-rest regain = ⌊total/2⌋ min 1, FIFO by position. Plan + audit: `docs/multiclassing-plan.md`
- Rests: `applyRest(character, features, {type, hitDiceSpent, healedHp})` (pure) — short: pact slots, wild shape, short-rest catalog counters, hit-dice spending where the PLAYER rolls at the table (we count dice + apply the announced healing, capped at max HP, clears death saves); long: full HP, temp 0, all slots, half-level hit dice back (min 1), exhaustion −1, concentration off, all counters (max recomputed). `POST /api/characters/:id/rest` persists + HP-mirrors to combatants. Food/water & conditions deliberately untouched
- Survival: variant encumbrance, food/water deprivation, exhaustion 1–6, death saves, 16 conditions (synced sheet↔tracker with durations), hit dice counter, inspiration, class-resource steppers (catalog counters) in Survie, Repos court/long buttons
- Paladin: Divine Smite quick-action on melee weapon cards (consumes a slot), Aura de protection (+CHA min 1 in own saves from level 6)
- Expertise (double proficiency bonus): `skillExpertise`/`toolExpertise` on characters, slots per SRD (`expertiseSlots`: Roublard 2@1/4@6 — compétences ou outils de voleur sharing one pool via `expertiseUsed`, Barde 2@3/4@10, Clerc Savoir 2@1); Compétences tab rows cycle ○ → ● → ◉ with strict slot gating + reminder banner; passive perception doubles with Perception expertise; Artificier 6+ gets automatic double on all tools (`hasAutomaticToolExpertise`, display note only). Outils (39 SRD tools, `DND_TOOLS` — labels match the item catalog) & Langues (`DND_LANGUAGES` 16 SRD + argot des voleurs/druidique, custom strings allowed) live below Compétences; enforcement is UI-side — the API stores whatever is PATCHed

### API routes (`apps/api/src/routes/`)
auth, characters (incl. HP/concentration/condition sync side-effects), inventory, items, spells (incl. `/light`), monsters, character-spells, character-features (catalog-aware: `catalogId` derives counterMax from the SRD formula), character-notes, locations, npcs (**secret = GM ALONE**: read AND write — a player's POST never stores one, a player PATCH carrying `secret` is ignored on that field, `mapNpc(row, gm)` gates every response), parties, combat (encounters, combatants, multi-add players, initiative, next-turn with condition expiry, **hidden monster names**: `combatants.name_hidden` — GM masks at add time or toggles from the card; the real name is redacted SERVER-side in `GET /encounters/:id` + rosters for non-GM viewers, players get `HIDDEN_COMBATANT_NAME` (« Créature inconnue ») instead; grouped monsters share the mask — PATCH fans out, late group joiners inherit it), campaign (**carnet du MD** — `GET /parties/:id/campaign` returns the whole notebook in one call: `campaign_state` (jour/saison/météo + **note du jour** — ligne créée au premier accès), `campaign_days` (registre des jours passés : une ligne PAR JOUR AVEC MÉTÉO **OU** NOTE — l'avance fige les deux, `PATCH /campaign-days/:id` retouche a posteriori et retire la ligne si on vide les deux), `campaign_countdowns` (cible = jour ABSOLU, l'affichage « J−N » est dérivé), `dm_notes` + `dm_quests` (statut CHECK preparation/active/done/failed); `POST …/campaign/advance {steps≤30}` archive+avance en effaçant météo et note (la correction directe `PATCH {day}` n'archive PAS — la météo reste celle d'aujourd'hui) — TOUT GM-only (403 sinon), broadcast `campaign:change` action clock/note/quest/countdown, signal sans payload : les joueurs reçoivent l'événement mais n'ont ni porte ni écouteur ; l'horloge ne touche JAMAIS les fiches — nourriture/eau/repos restent sur les feuilles), domain-spells, wildshape, rest (`POST /characters/:id/rest`). Shared helpers in `helpers.ts` (mappers, party checks, condition/HP mirrors). Rate limiting is a global hook in `rateLimit.ts`, not per-route config.

### Testing workflow
- Unit-ish: `npm run test-weapon-stats` / `test-armor-stats` (tsx, exit non-zero on failure) — extend these when adding rules
- **API data queries**: `npm run test-api` — boots a throwaway tsx server on a free port (fresh temp SQLite + seeds), runs the 11 domain modules in `scripts/api-tests/` (auth/parties, characters, items, inventory+locations, spells, features+notes, npcs+monsters, combat, multiclassage, wildshape+rests, websocket sync) over HTTP with a read-only DB connection for state asserts, then gates on **zero raw SQL**: any `.prepare(` site in routes/** + sync/** fails the run (the Drizzle migration completed 2026-08; scraper in `scripts/api-tests/coverage.ts` is whole-file, multi-line literals included). Fakes one `x-real-ip` per request so error-scoped rate limiting never trips
- **Browser E2E**: `npm run test:e2e` — Playwright suite in `e2e/` (viewport 390×844, French specs, `workers: 1`). The config's `webServer` array boots BOTH processes: tsx API on `E2E_API_PORT` (default 4740) with a fresh `data/db/e2e.sqlite` deleted at every launch + `JWT_SECRET`/loose rate limits, and vite dev on `E2E_WEB_PORT` (default 5175) proxying `/api`+`/ws`. `e2e/global-setup.ts` seeds the campaign over REST (GM `maitre` + player `lyra`, party, Guerrier/Clerc sheets, un-started « Embuscade gobeline ») into `e2e/.seed.json` (gitignored); `e2e/fixtures.ts` injects sessions via localStorage (`playerTest`/`gmTest`) — no UI login dance. Covers lazy-route resolution, inventory mutations (react-query invalidate→refetch), HP persistence, spell-slot casting, GM combat flow and live WS sync (GM tracker damage → player sheet updates without reload). Never touches dev/Docker DBs. CI: separate `e2e` job in `ci-test.yml` (chromium install + artifacts on failure)
- **Typecheck/build gates**: web `tsc -b` is clean and CI-enforced (`.github/workflows/ci-test.yml` runs lint + the 5 rules suites + web/shared typecheck + `test-api` on every PR and push to main; `Dockerfile.web` also typechecks before `vite build`); API smoke test = `PORT=4597 npx tsx src/server.ts` + curl `/api/health`

### Agent-environment gotchas (this machine)
- zsh does NOT word-split unquoted variables — `$FILES` passes as ONE argument (ENAMETOOLONG). Use `find … -exec cmd {} +` or explicit lists
- The shell cwd resets between tool calls — always `cd` first; the repo sits inside a space-containing parent folder (the campaign workspace), while the local project folder keeps its historical name `dnd-inventory` even though the GitHub repo is `table-sync`, and this AGENTS.md is committed at the repo root
- `typescript@7` has no JS API (see above); throwaway AST tooling should install `typescript@5` standalone (e.g. `/tmp/ts5`) and require it by absolute path
